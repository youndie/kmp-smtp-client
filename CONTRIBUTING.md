# Как здесь работают

## Правило одно

> **Сначала тест по документации, потом код. Прохождение теста — GATE.**

Тест обязан ссылаться на конкретную строку RFC в [`docs/rfc/`](docs/rfc/) — в KDoc над тестовым
классом или в комментарии над проверкой: `docs/rfc/rfc5321.txt:2642`. Тест, написанный «по здравому
смыслу», не принимается: SMTP полон мест, где здравый смысл расходится со спецификацией, и цена
такой ошибки — молча испорченное письмо у пользователя библиотеки.

Порядок в задаче:

1. прочитать место в RFC;
2. написать тест — он должен упасть;
3. убедиться, что он упал **по той причине, по которой должен** (не из-за опечатки в имени класса);
4. реализовать;
5. зелёный;
6. `./gradlew ktlintCheck`.

Пример полного цикла — задача M-07 в [BACKLOG.md](BACKLOG.md) и то, что от неё осталось в
`smtp-core/src/commonTest/.../SmtpReplyTest.kt`.

## Сборка и тесты

```bash
./gradlew macosArm64Test
```

Локальный цикл идёт на хостовом таргете, потому что тесты `linuxX64` на macOS запустить нельзя.
Полный прогон:

```bash
./gradlew build
```

На macOS он компилирует и линкует все три таргета, гоняет тесты `jvm` и `macosArm64` и пропускает
`linuxX64Test`. Закрывающий прогон вехи — на Linux, в CI.

## Стиль

ktlint 1.8.0, подключён как CLI, стиль `ktlint_official`, настройки в
[.editorconfig](.editorconfig).

```bash
./gradlew ktlintFormat
```

## Что должно быть в PR

- тест со ссылкой на RFC — раньше кода в истории коммитов, а не после;
- обновлённые документы, если изменилось описанное поведение (правило: если после вливания
  какой-либо документ станет враньём — правьте его этим же PR);
- отмеченная задача в [BACKLOG.md](BACKLOG.md).

Документация — русская проза; идентификаторы, команды SMTP и ключевые слова расширений пишутся
вербатим, как на проводе (`MAIL FROM`, `STARTTLS`, `8BITMIME`).

## Чего не делать

Список ловушек, каждая из которых уже стоила разбирательства, — в
[CLAUDE.md](CLAUDE.md#чего-не-делать). Коротко: не подключать `ktor-network-tls` (на Kotlin/Native
это заглушка), не тащить чужие типы буферов в `:smtp-core`, не сопоставлять ответы сервера с
командами по коду ответа.
