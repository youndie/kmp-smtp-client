**GATE закрыт.** 68 тестов зелёные на `linuxX64` (Linux-машина, задача `linuxX64Test`
выполняется), на `jvm` и на `macosArm64`; `ktlintCheck` чист.

**Итог M1.** Четыре вещи вылезли сверх плана — каждая из чтения RFC, а не из кода.

Предел строки задан **в октетах**, а не в символах: с SMTPUTF8 разница двукратная, и наивная
проверка по `length` пропускает вдвое больше положенного. Проверка октетов теперь в каждом
пределе — строка ответа, командная строка, части адреса, строка тела.

Вторая цифра кода ответа намеренно не проверяется, хотя ABNF (`rfc5321.txt:2600`) её ограничивает:
`rfc5321.txt:3043` требует от клиента разбирать неизвестные коды по первой цифре, и ломаться из-за
чужой небрежности дороже, чем принять код.

Предел строки тела считается **до** удвоения ведущей точки (`rfc5321.txt:3512`) — иначе законная
строка из 998 символов, начинающаяся с точки, отвергалась бы своим же клиентом.

У `AUTH` слишком длинный начальный ответ — не ошибка, а повод не использовать этот параметр
(`rfc4954.txt:208`); токены OAuth задевают предел всерьёз. Поэтому у команды есть `fitsLineLimit`:
спросить можно заранее, а не узнать исключением на отправке.

- [x] **M-25** Результат отправки как структура «принятые / отвергнутые получатели с кодами», а не исключение ([protocol-smtp §10](docs/api/protocol-smtp.md))
- [x] **M-26** Классификация ошибок: постоянные (5xx) / временные (4xx) / транспортные
- [x] **M-27** `RSET` между транзакциями в одном соединении

**GATE закрыт.** 93 теста зелёные на `linuxX64` и на `jvm` (Linux-машина, E2E против Mailpit
включён), на macOS — те же за вычетом E2E; `ktlintCheck` чист.

**Итог M2.** M-22 (сброс после `AUTH`) переехал в M5: механика сброса написана и работает в
`startTls`, но проверять её на `AUTH` нечем, пока нет ни одного механизма SASL. Закрывать задачу
кодом, который никто не вызывает, значит соврать в чек-листе.

M-31 (сценарный транспорт) сделан здесь, а не в M3: без него сессию нечем тестировать, а сокет
ради этого поднимать незачем.

Главная находка вехи — **устаревшие `Capabilities` должны падать, а не просто устаревать**.
Значение, полученное до `STARTTLS`, после рукопожатия начинает бросать исключение: клиент,
доверяющий списку расширений «до TLS», уговаривается на downgrade активным посредником
(`rfc3207.txt:210`). Цена — публичный `markStale()` на типе-значении; вынесено в грабли
[smtp-core](docs/services/smtp-core.md).
