# smtp-core

## 1. Зона ответственности

Протокол SMTP как набор функций над строками и байтами: разбор ответов сервера, сериализация
команд, разбор расширений из `EHLO`, прозрачность данных, модель адресов и конверта, состояние
сессии. Плюс порты — интерфейсы, через которые всё это получает ввод-вывод.

**Чем не занимается:** сокетами, TLS, криптографией, DNS, построением письма. Ничего из этого
модуль не подключает даже транзитивно — у него нет зависимостей, кроме stdlib. Это и есть условие
того, что почти все тесты проекта идут без сети (см. [research Р3](../research/research-architecture.md)).

Главный инвариант: **в `:smtp-core` не попадает ни одного типа из чужой библиотеки** — ни
`ByteReadChannel` из Ktor, ни `Source` из kotlinx-io ([research Р8](../research/research-architecture.md)).
Как только он попадёт, фейк для теста начнёт требовать реализации чужого интерфейса.

## 2. Контракт

Что модуль обязан уметь и по каким правилам — [protocol-smtp](../api/protocol-smtp.md).
Источник правды для обоих — тексты в [`docs/rfc/`](../rfc/).

## 2а. Ключевые файлы (якоря кода)

Всё лежит в `src/commonMain/kotlin/io/github/youndie/smtp/protocol/`, тесты — зеркально в
`src/commonTest/`.

| Файл | Что там |
|---|---|
| `SmtpReplyCode.kt` | трёхзначный код и исход по первой цифре |
| `SmtpReply.kt` | ответ целиком; `SmtpReplyLine` — разбор одной строки и пределы |
| `SmtpReplyReader.kt` | потоковое чтение: строки на входе, ответы на выходе |
| `EnhancedStatusCode.kt` | расширенный код `X.Y.Z` |
| `SmtpCommand.kt` | команды и их сериализация |
| `Capabilities.kt` | разбор ответа на `EHLO` |
| `Mailbox.kt` | адрес и путь конверта |
| `MailData.kt` | прозрачность данных и предел строки тела |
| `SmtpProtocolException.kt` | нарушение протокола (не отказ сервера) |

Ещё нет: состояния сессии (M2) и портов ввода-вывода (M-30, M-40).

## 3. Как устроено

Разбор ответа идёт **сверху вниз через один вход**: `SmtpReplyReader.feed` принимает строку без
`CRLF`, `SmtpReply.parse` — просто прогоняет через тот же читатель список строк. Резать поток на
строки — дело транспорта, протокольный слой байтов не видит.

Читателю не сообщают, на какую команду ждут ответ, и это не упущение: при PIPELINING ответы
сопоставляются с командами счётом, а по коду или тексту — прямо запрещено
(`docs/rfc/rfc2920.txt:177`). Сопоставлением займётся слой сессии.

Все пределы длин считаются **в октетах** (`value.encodeToByteArray().size`), а не в символах:
`docs/rfc/rfc5321.txt:3498` и соседние задают их именно так, и с SMTPUTF8 разница двукратная.

## 4. Зависимости

Никаких. `kotlin("test")` — только в `commonTest`.

## 5. Конфигурация

Нет. Таймауты и лимиты станут значениями с дефолтами из RFC на M-24.

## 6. Сборка

Модуль подключает конвенцию `smtp.kmp` (`build-logic/src/main/kotlin/smtp.kmp.gradle.kts`):
таргеты `linuxX64`, `macosArm64`, `jvm`, `explicitApi()`, `allWarningsAsErrors`.

```bash
./gradlew :smtp-core:macosArm64Test   # локальный цикл
./gradlew build                       # всё, что можно на этом хосте
```

## 7. Сознательные ограничения / грабли

* **`macosArm64` в списке таргетов — инструмент, а не поддерживаемая платформа.** Тесты `linuxX64`
  на macOS не запускаются, и без хостового таргета цикл TDD невозможен
  ([research Р9](../research/research-architecture.md)). Транспорт и TLS под apple делаются на M8.
* **`linuxX64Test` на не-Linux хосте выключается самим KGP**, а `kotlin.native.ignoreDisabledTargets=true`
  в `gradle.properties` глушит предупреждение об этом. Если однажды окажется, что тесты «зелёные»,
  а никто их не запускал, — смотреть сюда. В CI (ubuntu) задача включена, и веха закрывается там.
* **Кросс-компиляция `linuxX64` с macOS работает** — `linkDebugTestLinuxX64` собирается локально.
  Не работает только запуск.
* **`explicitApi()` включён**: у каждого публичного объявления видимость и тип возврата пишутся
  руками. Это шум в диффе ровно один раз, зато публичный API библиотеки нельзя расширить случайно.
* **Вторая цифра кода ответа не проверяется**, хотя ABNF (`docs/rfc/rfc5321.txt:2600`) её
  ограничивает диапазоном 0–5. `docs/rfc/rfc5321.txt:3043` велит клиенту разбирать неизвестные
  коды по первой цифре; строгость здесь означала бы падение из-за чужой небрежности.
* **`Capabilities.maxMessageSize == null` — это не «ноль байт»**, а «предел неизвестен»:
  `docs/rfc/rfc1870.txt:79` разводит `SIZE 0` («фиксированного предела нет») и `SIZE` без значения
  («ничего не сообщается»), но для клиента оба означают одно.
* **Предел строки тела считается до удвоения ведущей точки** (`docs/rfc/rfc5321.txt:3512`). Иначе
  законная строка из 998 символов, начинающаяся с точки, была бы отвергнута своим же клиентом.
* **В именах тестов нельзя ставить запятую**: Kotlin/Native отвергает такое имя в обратных
  кавычках («Name contains illegal characters»), хотя на JVM оно компилируется. Ловится только
  сборкой нативного таргета.
